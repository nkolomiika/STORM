# Уязвимости

Уязвимости (находки) — ядро проекта. Каждая находка привязана к хосту и несёт критичность, оценку CVSS, шаги воспроизведения, влияние и рекомендации. Работа с находками — во вкладке **Vulnerabilities** проекта.

## Как завести находку

1. Откройте проект → вкладка **Vulnerabilities**.
2. Нажмите кнопку добавления находки.
3. Заполните быструю форму:
   - **Title** — краткая суть находки.
   - **Affected host** — находка обязана относиться к хосту; выберите его из списка хостов проекта.
   - **Severity** — критичность (см. ниже).
   - **Status** — обычно `open` для новой находки.
4. Сохраните. Откроется карточка находки, где заполняются остальные поля.

> Если нужного хоста ещё нет, сначала заведите его во вкладке **Recon → Hosts** (см. главу «Хосты и активы»).

## Критичность (severity)

Возможные значения: **critical**, **high**, **medium**, **low**, **info**, **unrealized**.

У новой находки критичность по умолчанию — **info**. Как только у находки появляется вектор **CVSS**, критичность вычисляется из него автоматически. Чтобы поменять её у находки с CVSS, редактируйте **CVSS-вектор** на карточке.

**unrealized** («не реализуема») — для находок без CVSS, которые проверены и признаны неэксплуатируемыми. Такие находки, как и **info**, попадают в отчёте только в раздел «Тесты», но не в детальный перечень уязвимостей (см. главу «Отчёты»).

## Поля карточки находки

- **CWE ID** — тип слабости из каталога CWE (например, `CWE-89`).
- **CVSS 4.0 вектор** — вводится текстом (строка вектора); рядом сразу показываются рассчитанные **балл** и **критичность**.
- **Status** — статус находки (см. ниже).
- **Steps to reproduce** — шаги воспроизведения нумерованным списком: шаги можно добавлять и удалять. В шаг можно вставить скриншот из буфера обмена (открывается по клику).
- **Impact** — влияние.
- **Remediation** — рекомендации по устранению.

## Статусы находки

Статусы совпадают с воркфлоу Task Tracker (Works «BUG APPSEC»), всего девять, сгруппированы в три категории:

- **Ожидание**: **open** (открыта), **need info** (нужна информация), **paused** (на паузе).
- **В работе**: **in progress** (в работе), **problem analysis** (анализ проблемы).
- **Завершено**: **resolved** (решена), **closed** (закрыта), **cancelled** (отменена), **sent by mistake** (заведена по ошибке).

Цвет статуса отражает смысл: открытые и решённые — зелёный, в работе — синий, need info — янтарный, cancelled — красный, paused/closed/sent by mistake — серый.

Статус меняется на карточке находки через выпадающий список **Status** (в стиле приложения, со всеми девятью статусами). Когда статус меняется, **автор находки получает уведомление**.

## Редактирование и экспорт

Карточка находки редактируется **прямо на месте** (инлайн): правьте поля и сохраните кнопкой **Save changes** внизу карточки. Отдельной модалки и «карандаша» в списке больше нет — чтобы изменить находку, откройте её карточку.

На линии заголовка карточки — кнопки экспорта:

- **Export to AppSec** — создаёт тикет `BUG_APPSEC` в Works (пространство STS) с резолвом компонента, затронутой версии и исполнителя. Доступна при включённой интеграции Works. Ссылка на созданный тикет — в формате Works.
- **Export to Task Tracker** — выгрузка находки в задачу Task Tracker (в статусе To Do, с деталями находки).

## Фильтры

Список уязвимостей можно фильтровать по **критичности** и **статусу** (мультивыбор), а также по **автору** и **хосту**. В фильтре статуса показываются пять основных состояний воркфлоу (**open**, **in progress**, **resolved**, **closed**, **cancelled**); на карточке находки в выпадающем списке доступны все девять.


### Info и Unrealized при экспорте в Task Tracker

**Info** можно экспортировать отдельно или массово: приоритет `trivial`,
CVSS-вектор сохраняется, поле CVSS-критичности не заполняется.
**Unrealized** не экспортируются: кнопка бледная с объяснением, массовый экспорт
пропускает их и показывает количество исключённых находок. Прямой API-запрос
экспорта Unrealized также отклоняется до обращения к TT.
