# Проверка внутренних методов STORM

Последний полный прогон 13 ноября 2026 года: **915 backend-тестов и 235 frontend-тестов прошли, пропусков нет; сборка tsc/Vite успешна**. В набор входят 26 проверок границ запуска процессов без внешних сканеров, некорректные входные данные и регрессии безопасности. Внешние адаптеры исключены из отдельной метрики backend: 81,16% строк / 63,30% ветвей; frontend: 65,05% / 57,55%. Полного покрытия пока нет; после повторного успешного прогона владелец отдельно разрешил push в GitHub. Результаты и команды: [TEST_COVERAGE.md](TEST_COVERAGE.md), исправления и остаточные риски: [SECURITY_AUDIT.md](SECURITY_AUDIT.md). Числа ниже относятся к предыдущим этапам проверки.

По результатам проверок 10–11 ноября 2026 года исправлены ошибки HTTP 500, нарушения доступа между проектами и сбой JSON-импорта. Регрессионные тесты проверяют исправленное поведение на настоящем PostgreSQL, без вызовов внешних систем.

После итогового прогона локальный backend перезапущен: `/health` и UI через nginx отвечают 200, запрос профиля без авторизации — 401. Защитные заголовки присутствуют. `pip check` не находит конфликтов зависимостей. В pytest остаются три предупреждения о deprecated `crypt`/FastAPI startup events; некорректные асинхронные моки синхронного `Session.add` исправлены, RuntimeWarning о незавершённых корутинах больше нет.

## Исправленные дефекты

| Сценарий | Поведение до исправления | Причина и расположение |
| --- | --- | --- |
| PUT хоста с новым hostname, notes, status, IP или пустым объектом | 500 вместо 200 | `AssetService._get_host` не загружает `Host.endpoints`; `HostOut` вызывает ленивую загрузку вне async greenlet |
| POST нового хоста с hostname или IP | 500 вместо 201 | Та же незагруженная связь `endpoints` при сериализации |
| POST, GET и PUT порта, GET непустого списка портов | 500 вместо успешного ответа | `PortOut.services` обращается к незагруженной коллекции; `_get_port`, `list_ports`, `create_port`, `update_port` не обеспечивают её загрузку |
| GET проектов с `status=invalid` | 500 вместо 422 | Строковый фильтр поступает в PostgreSQL Enum без валидации |
| GET хостов с `status=invalid` | 500 вместо 422 | Аналогичная ошибка фильтра |
| GET уязвимостей с неверным status или severity, включая список по хосту | 500 вместо 422 | Аналогичная ошибка фильтра |
| GET чужих сервисов, эндпоинтов и комментариев через URL доступного проекта | 200 с чужими данными вместо 404 | Проверка доступа к project_id не проверяет принадлежность вложенного объекта этому проекту |
| DELETE чужого порта, сервиса или эндпоинта через URL доступного проекта | 204 и удаление чужой записи вместо 404 | Вложенные методы удаления не проверяют всю цепочку project → host → port → service/endpoint |
| GET/PUT чужого порта через URL доступного проекта | 500 вместо отказа | Отсутствует проверка принадлежности проекту; ошибка сериализации дополнительно маскирует проблему |
| Импорт JSON с новым hostname и ip_address | 422 «Невозможно импортировать порты: у хоста нет IP-адресов» | `ImportService.import_json` создаёт Host, но не HostIpAddress, затем безусловно требует primary IP даже при отсутствии портов |

Устранённые ошибки сериализации возникали после записи в БД: методы создания/изменения выполняют commit до формирования HTTP-ответа. Теперь Host.endpoints и Port.services загружаются явно, поэтому сериализация проверенных сценариев больше не вызывает MissingGreenlet.

Вложенные сервисные методы теперь проверяют project → host → port и принадлежность уязвимости проекту до чтения или изменения данных. Проверки доступа выполняются обычным pentester, добавленным только в первый проект. Второй проект и его ресурсы создаются отдельно. После отказа тест дополнительно проверяет сохранность чужих портов, сервисов и эндпоинтов. Тесты удаляют только данные своей временной схемы.

Фильтры статуса и критичности принимают Enum на уровне FastAPI и возвращают 422 для некорректных значений. JSON-импорт создаёт недостающую HostIpAddress; отсутствие IP отклоняется только при импорте портов. Проверяются hostname без IP и IP с портами и сервисами.

## Фронтенд

Инициализация авторизации больше не сбрасывает восстановленную сессию при повторном mount. При открытии `/login` с неизвестным состоянием сессии приложение проверяет cookie на сервере. Новые тесты `store.test.ts` проверяют восстановление сессии, повторный mount и отказ сервера. HTTP-вызовы авторизации в тесте маршрутизации замоканы.

Исправлены тип функции `markdownUrlTransform` и тип ID изображений при удалении шага воспроизведения. Все тесты фронтенда (134) и `npm run build` проходят. В логах остаются предупреждения React `act`, библиотечные deprecation warnings и предупреждение Vite о размере чанка; они не приводят к падению проверок.

## Запуск проверок

Из корня репозитория, с запущенным локальным PostgreSQL:

```bash
docker compose up -d db minio rabbitmq backend frontend nginx
docker compose exec -T \
  -e STORM_TEST_DATABASE_URL=postgresql+asyncpg://user:password@db:5432/storm \
  backend python -m pytest -q --tb=short --junitxml=/tmp/storm-tests.xml
```

Учётные данные в команде соответствуют локальному `docker-compose.yml`. Переменная `STORM_TEST_DATABASE_URL` включает тесты PostgreSQL; без неё они явно пропускаются. Каждый тест создаёт собственную схему `test_<uuid>` и удаляет её в `finally`, не очищая существующие таблицы приложения. Полный прогон после исправлений завершается с кодом 0.

Для полного traceback вместо HTTP 500 добавьте `-e STORM_TEST_RAISE=1` перед `backend`.

```bash
cd frontend
npm test -- --reporter=dot
npm run build
```

Внешние системы не входят в новые сценарии: нет обращений к Works, Jira, SSO, SMTP, сканируемым хостам или MinIO. Почта в HTTP-тестах принудительно отключена; Word-отчёты проверяются без внешних файлов. Startup приложения в тестах не запускается. Внутренний PostgreSQL используется намеренно, чтобы воспроизводить реальные ORM-ошибки и ограничения БД.

## Дополнение: архитектура и нагрузка

После первого функционального аудита добавлены пять регрессий полноты данных/масштабирования SQL и реальная проверка concurrent-миграции индексов. Чтение комментариев и уведомлений больше не выполняет SQL внутри цикла. На фронтенде устранены запросы карточек для каждой строки находок и квадратичное построение иерархии хостов. Подробности и ограничения: [архитектурное ревью](ARCHITECTURE_REVIEW.md), [нагрузочные замеры](PERFORMANCE.md), [каталог методов](METHODS.md).

Для графиков проектов добавлены ещё две PostgreSQL-регрессии: лёгкий список дат совпадает с полными хостами (включая origin=ip и одинаковые даты), не загружает дочерние таблицы и соблюдает права проекта. UI-тест проверяет, что главная страница не скачивает деревья хостов, а открытие проекта продолжает их загружать.

## Дополнение: оформление Creds и каретка изображения

Creds использует шапку Inter и ту же поверхность, что Hosts/JS/IPs, отступы строк 15×20, сетку с gap 14 и gap 2 для действий. Пароли остаются замаскированы, показ и копирование сохранены.

В изолированном headless Chrome воспроизведена каретка двумя отрезками сверху/снизу высокого non-editable image node view. Добавлен `ImageCaret`: при свёрнутой TextSelection рядом с изображением отображается одна view-декорация, а нативный визуальный курсор скрывается. Сам ввод и позиция ProseMirror не заменяются. Подтверждены единичная каретка и ввод текста после изображения; Markdown сохраняет ширину, не получает символов декорации. Тесты проверяют отсутствие индикатора при NodeSelection/диапазоне и его исчезновение после ввода, а существующие сценарии — resize и drag/drop.

По уточнению владельца изображение выровнено по baseline: каретка и вводимый справа текст расположены снизу картинки. Нижнее положение проверено в Chrome. Удалены остаточные упоминание My Tasks во встроенной инструкции и неиспользуемый перевод текста приглашения.

## Дополнение 11 ноября: новые подтверждённые ошибки

| Сценарий | До | После и проверка |
| --- | --- | --- |
| WebSocket с действительным access JWT | SQL `INTEGER = VARCHAR` из-за строкового sub; соединение падает до регистрации | Общий decode_token преобразует sub в int, state.user_id остаётся числом; PostgreSQL-регрессия проверяет вход и доставку уведомления |
| Клиент отключился во время await send_json | Изменение set прерывает рассылку с RuntimeError | Снимок адресатов; регрессии для комнаты проекта, персонального канала и уведомлений через проектную комнату |
| Файл/картинка, JS ZIP или Word-отчёт с русским именем | HTTP 500 при кодировании Content-Disposition в latin-1 | UTF-8 filename*, ASCII fallback отчёта; проверяются байты ответа и восстановление имени |
| Post comment в окне эндпоинта | Кнопка только закрывала окно, данных в БД не было | Отдельная таблица, GET/POST API, постоянное обсуждение в UI; после закрытия и повторного открытия запись загружается снова |
| Save changes эндпоинта без изменений | Кнопка исчезала | Всегда видна; disabled и бледная при неизменённом тексте, загрузке и сохранении |

Новые тесты WebSocket воспроизвели 7 падений из 12 сценариев до исправления; все 12 проходят после. Проверки заголовков скачивания воспроизвели 5 падений из 7; все 7 проходят после. Хранилище файлов и сборщик JS-архива в этих сценариях подменены, внешних запросов нет.

Обсуждения эндпоинтов проверены на сохранение, автора, отказ для чужого проекта/хоста и неучастника, пустой текст, стабильную пагинацию 110 записей без N+1, каскадное удаление, атомарный откат при отказе аудита и повторный upgrade новой миграции. UI-тесты проверяют повторное открытие окна, защиту от двойной отправки, сохранение черновика при ошибке, повтор страницы и игнорирование запоздавшего ответа другого эндпоинта. Ошибка аудита в тесте намеренно подставляется; это проверка отката новой операции, а не устранение прежней общей проблемы AuditService.

Исправлен путь `export_openapi.py` в compose: из `/app` скрипт теперь находит репозиторий `/workspace`, а не пишет в `/docs` внутри контейнера. Проверено наличие новых путей комментариев и host-creation-times в JSON рабочей копии; справочники пересозданы из этих спецификаций.
