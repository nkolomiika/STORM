# Аудит безопасности STORM

Проверка 13 ноября 2026 года охватывает внутренние HTTP/WebSocket-границы, авторизацию, обработку недоверенных данных, файлы, JS-сканирование и зависимости. Подтверждённые ошибки исправлены и закреплены регрессиями. Остаточные риски перечислены отдельно: это аудит кода и локального стенда, а не заключение о защищённости внешних IdP, сканируемых систем или production-инфраструктуры.

Итоговая проверка: 915 backend-тестов с изолированными схемами PostgreSQL и 235 frontend-тестов проходят без пропусков, tsc/Vite build проходит. Покрытие внутреннего backend — 81,16% строк / 63,30% ветвей, frontend — 65,05% / 57,55%; полного покрытия нет. Подробная область измерения и воспроизведение — [TEST_COVERAGE.md](TEST_COVERAGE.md).

## Исправленные проблемы

| Область | Проблема | Изменение и доказательство |
| --- | --- | --- |
| SSO и захват аккаунта | Поиск существующего пользователя по username мог сопоставить другую IdP-личность с локальным администратором | Удалён fallback по username; нужен подтверждённый email. Проверяется соответствие userinfo.sub исходному ID-токену. Совпадение имени теперь создаёт отдельного pentester, а неподтверждённый email отклоняется |
| Подпись OIDC | Алгоритм брался из неподтверждённого заголовка токена | Разрешены только явные RSA/ECDSA алгоритмы, HMAC отклоняется до загрузки JWKS; алгоритм JWK должен совпадать. Обязательны exp/iat/sub, проверяются issuer/audience/nonce. Есть реальная проверка локально подписанного RSA-токена без IdP |
| Агентские токены | Блокировка/деактивация владельца не прекращала доступ | Чтение и запись получают 401 до обновления last_used_at; проверки выполняются при каждом HTTP-запросе |
| Неверные данные | NUL и слишком большие числа доходили до PostgreSQL и вызывали 500 | Общие границы ID/path/query, рекурсивная проверка строк/чисел и диапазон целочисленных полей. Неверные данные возвращают 422 |
| Конфигурация токена | Несуществующий project_id давал ошибку FK; expires_at без timezone вызывал TypeError | Проверяются существование проектов и timezone; неверный запрос не создаёт частичную запись |
| Пароли | Обычный bcrypt не учитывает суффикс после 72 байтов | Новые/изменённые пароли хэшируются bcrypt_sha256. Старые bcrypt-хэши продолжают проверяться; их полная миграция происходит при смене пароля. Тест сравнивает два длинных пароля с одинаковыми первыми 72 байтами |
| Перебор входа | Публичные операции авторизации не ограничивали попытки | Ограничитель по клиенту и аккаунту/ссылке: 429 и Retry-After. Ключи хэшируются, память ограничена, старые попытки истекают |
| JS-секреты | Полное значение могло оставаться в snippet, несмотря на замаскированное preview | Маскируются контекст regex-находок и контекст jsluice, включая соседние распознанные секреты |
| Парсеры инструментов | Валидный JSON неожиданного типа мог приводить к TypeError/AttributeError | Проверяются типы объектов, полей и коллекций. Детерминированный корпус из 250 вложенных документов проходит все парсеры без сети |
| Загрузка файлов | Файлы читались целиком до проверки размера, MIME картинки определялся заголовком | Чтение ограничено limit+1 байтами; превышение → 413. Картинки проверяются Pillow, MIME и расширение берутся из байтов. HTML с image/png отклоняется до обращения к хранилищу |
| YAML | Alias-граф мог быть рекурсивным или резко увеличивать объём обработки | Aliases отклоняются, поддерживаются обычные OpenAPI $ref. Ограничены вложенность и недопустимые значения; Python object-construction tags не исполняются |
| WebSocket | Не проверялся Origin; бинарный кадр мог оборвать обработчик и оставить подключение | Чужой Origin отклоняется до БД. Текстовые/бинарные keepalive принимаются, при disconnect регистрация всегда очищается. Project ID ограничен до SQL |
| HTTP-заголовки | Не было общей защиты от MIME sniffing, iframe и передачи токена ссылки в Referer | API добавляет nosniff, no-referrer, DENY и no-store, сохраняя явную политику кеширования изображений. Nginx задаёт браузерные защитные заголовки также для UI |
| Внутренние порты | Production override наследовал опубликованные backend/PostgreSQL/MinIO | `ports: !reset []` удаляет публикацию. Итоговый compose config проверен без запуска production-стека; нужен Compose 2.24+ |
| Внешнее хранилище в конструкторах | Создание UserService/FileService обращалось к MinIO до необходимости работы с файлом | Проверка/создание bucket перенесена к загрузке. API-тесты запрещают незамоканные storage-вызовы; отказ в доступе к файлу проверяется до чтения blob |

Атомарность CRUD и аудита, конфликт заметок, очистка notes=null, счётчики хостов и догрузка находок описаны в [архитектурном ревью](ARCHITECTURE_REVIEW.md). Это также снижает риск повторной отправки после 500 и скрытых частичных изменений.

## Проверенные защитные границы

- SQL-подобная строка в названии проекта сохраняется как текст, таблицы остаются доступны. Запросы используют параметры SQLAlchemy.
- Неучастник не читает чужие файлы и креды; JSON-поля role/is_locked в изменении собственного профиля не повышают права. Пароль креда хранится зашифрованным и не копируется в аудит.
- Неправильные Origin и session/JWT types отклоняются. Подписанный токен с отрицательным, огромным или неверно типизированным sub не вызывает SQL-ошибку.
- Одноразовые ссылки проверены на отсутствие, истечение, повтор и параллельное использование; mutations блокируют строку токена до commit.
- В HTTP-тестах проверены неверная JSON-форма, повреждённая кодировка, глубоко вложенный JSON, NaN, невалидная пагинация, NUL, переполнение ID и SQL-синтаксис в данных. Допустимые ошибки клиента не подменяются безусловным успешным ответом.
- Командная инъекция через host/JS не воспроизведена: пять запусков процессов используют exec без shell, httpx-pd читает цели через stdin, TruffleHog получает случайный временный файл. Локальный процесс в тесте возвращает payload буквально, маркер выполнения команды не создаётся.
- Markdown не создаёт script/iframe/обработчики событий и опасные URL в проверенном корпусе. Обновлён TipTap с исправлением mergeAttributes/__proto__; есть регрессия на наследование onclick.

Основные наборы: `test_hostile_inputs.py`, `test_security_audit.py`, `test_security_boundaries.py`, `test_command_injection.py`, `test_api_guards.py`, `test_account_links.py`, `test_review_regressions.py` и `frontend/src/security.test.tsx`. Матрица доступа содержит 193 проверки. После обновления FastAPI её перечисление адаптировано к lazy included routers; минимальное число маршрутов проверяется assert, чтобы пустая матрица не превращалась в незаметный skip.

Обновлены FastAPI/Starlette, python-multipart, python-jose, Pillow, aiosmtplib, certifi/pyasn1, pip и тестовые библиотеки. Удалён Dockerfile-шаг, возвращавший Pillow 10.4 после установки requirements. На фронтенде обновлены Axios/YAML/Vite, TipTap 3, React Router 7 и Vitest. Совместимость проверяется полным прогоном, редактором, переносом/масштабированием изображения и tsc/Vite build; `setContent` адаптирован к API TipTap 3.

Оставшиеся npm-записи относятся к minimatch в цепочке typescript-eslint. [Advisory GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) описывает DoS через globparts и исправление в 11.0.1. По установленному дереву это инструменты разработки, не обработка пользовательских запросов STORM. Принудительная замена major-версии транзитивного пакета не выполнялась; эти 6 записей не скрыты через audit ignore.

В Python остаются [python-jose GHSA-3qf3-8w2g-rqmx](https://github.com/advisories/GHSA-3qf3-8w2g-rqmx) и [ecdsa GHSA-wj6h-64fc-37mp](https://github.com/advisories/GHSA-wj6h-64fc-37mp), без опубликованных исправленных версий на дату проверки. Вывод по коду STORM: HMAC-сессии используют отдельный симметричный секрет и явный HS256, OIDC отклоняет HS-алгоритмы; ECDSA signing/key generation не используются приложением, а advisory не затрагивает проверку подписей. Это ограничения достижимости известных сценариев, а не отсутствие уязвимых библиотек. Для полного удаления находок потребуется замена JWT-зависимости/инструментов; pip-audit дважды сообщает один и тот же ecdsa advisory, поэтому 3 записи не означают 3 разные уязвимости.

## Остаточные архитектурные риски и эксплуатация

1. Rate limit хранится в памяти процесса. Между workers/репликами нужен общий limiter на gateway/Redis; за reverse proxy следует настроить доверенную передачу реального IP. Не доверяйте произвольному X-Forwarded-For из интернета.
2. SSRF-проверки фильтруют адреса, в том числе IPv4 внутри IPv6, но DNS-проверка и соединение не являются одним атомарным действием. Внешние бинарные сканеры резолвят цели самостоятельно. Для строгой границы нужен сетевой egress policy/изолированный сканирующий процесс; регрессии не доказывают отсутствие DNS rebinding у сторонних утилит.
3. Уже открытые WebSocket не пересматривают членство/блокировку до reconnect; обычный access JWT после logout живёт до exp, тогда как refresh отзывается. Нужны общий отзыв сессий/соединений и межпроцессная доставка; это отличается от исправленной проверки при новом HTTP/WS-входе.
4. Объекты MinIO и транзакции PostgreSQL не образуют распределённую транзакцию. Для гарантированной очистки/компенсации при отказе внешнего хранилища нужен outbox. Реальные MinIO/SMTP/Works/Jira/IdP не тестировались; подменены только их границы.
5. Production frontend пока запускается через Vite dev server. Следующий этап — static build с отдельной раздачей и API/WS proxy. В Dockerfile сканеры скачиваются из latest release; для воспроизводимой supply chain нужны версии и проверенные checksum по архитектурам.
6. Существующие локальные bcrypt-хэши не преобразуются без нового пароля. SSO теперь требует email_verified=true; IdP должен выдавать этот стандартный claim. Эти требования необходимо учесть перед обновлением стенда.
7. Маскирование JS-контекста применяется при новом разборе. Ранее сохранённые snippets не переписывались автоматически: для исторических данных нужна отдельная проверка и очистка либо повторный скан с согласованным доступом к целям.
