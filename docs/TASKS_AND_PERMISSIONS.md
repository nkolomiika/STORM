# Проекты, задачи и права — 18 ноября 2026

## Права на проекты

| Действие | Admin | Lead | Pentester |
| --- | --- | --- | --- |
| Создать проект | Да | Да | Нет |
| Редактировать проект | Да | При членстве или авторстве | При членстве или авторстве |
| Удалить проект | Да | При членстве или авторстве | Только собственный |
| Открыть связанный проект из Tasks | Да | При наличии доступа | При наличии доступа |

Создатель автоматически становится участником. Запрет создания проверяется
зависимостью API, а не только отсутствием кнопки. Удаление использует общую
проверку администратора, создателя или лида-участника. Создатель сохраняет право
удаления и при отсутствии членства в старых данных.

Tasks возвращает `project_exists`, но `project_id` — только при наличии доступа.
Существующий недоступный проект обозначается серой папкой; несозданный проект —
плюсом, недоступным обычному пентестеру. Проверка принадлежности выполняется
каждый раз; результат проверки прав не кэшируется вместе с тикетами.

Создание и изменение привязки APPSEC сериализуются PostgreSQL advisory lock
по ключу тикета. Повторная привязка через сервис возвращает 409; это защищает
также от двух одновременных запросов. Без тикета проект сохраняется как раньше.

## Пагинация Tasks

В UI используются `category=active|closed`, `page_number` с нуля, `sort=first|last`
и необязательный `query`. Фильтрация и сортировка применяются **до** порции 20.
Ответ содержит `total` выбранной категории, `active_total`, `closed_total`,
`next_page_token`, `is_last`. Пауза относится к Closed.

Первая порция содержит до 20 подходящих тикетов. Следующая добавляет до 20;
подпись кнопки учитывает остаток. При 25 закрытых тикетах это 20/25 и
«Показать ещё 5», затем 25/25 без кнопки. Поиск и порядок действуют для всей
категории, а не только для уже видимых строк. В таблице исполнитель сокращён
до фамилии и имени; полное ФИО и affected versions сохранены в карточке.

Подтверждённый TQL не меняется догадками о синтаксисе фильтров статусов.
Для точных счётчиков строится общий индекс APPSEC: страницы до 100 записей,
не более четырёх запросов одновременно. При внешнем 422 первой страницы
повторяется подтверждённый размер 20. Если TT ограничивает размер молча,
учитывается фактический размер ответа. Ошибки не кэшируются.

Индекс живёт 60 секунд и используется обеими вкладками, поиском и сортировкой.
Refresh перестраивает его. Первый запрос требует чтения страниц; последующие
запросы используют готовый индекс. В нём не сохраняются описания и права на
проекты. Ключ включает отпечаток авторизации, tenant и параметры подключения.
Предел — 20 тысяч тикетов и четыре варианта подключения; превышение выдаёт
контролируемый отказ с предложением уточнить фильтр интеграции. Это защитный
предел памяти, а не молчаливое обрезание данных. Данные TT могут измениться
между чтениями; Refresh получает новый индекс.

Запрос без Active/Closed сохраняет прежний контракт нативных страниц. Полная
карточка по ключу читается непосредственно через подтверждённый unit/v2.

## Разблокировка и аватары

POST `/users/{id}/reactivate` доступен администратору и сразу снимает блокировку,
возвращая `UserOut`. SMTP, новое письмо и новый токен не используются. Старые
ссылки разблокировки гасятся. Пароль, роли, авторство и членство сохраняются.

Списки пользователей и участников возвращают `avatar_url`. Общий компонент
показывает фото, а при отсутствии или ошибке — первую букву username. Правило
одинаково в шапке и списках; замена URL позволяет повторно загрузить новое фото.

## Отчёты и STS

Название продукта берётся из части affected version перед версией; одинаковые
названия не дублируются. Суффикс версии сохраняется полностью. При отсутствии
названия продукта используется имя проекта. Меняются обложка, текст, карточки,
колонтитулы и имя скачиваемого файла; исходные значения проекта не меняются.

Info экспортируется с `trivial`, исходным вектором, если он задан, и без
CVSS-критичности. Unrealized исключается из массового экспорта; отдельная кнопка
недоступна с подсказкой. API также отклоняет Unrealized до обращения к TT.

## Локальная демонстрация и production

Явный запуск `python -m scripts.seed_ui_demo` добавляет 45 синтетических тикетов,
заполненные версии/компоненты/код продукта и отдельного демо-участника с фото.
Повторный запуск не создаёт копии и не меняет чужие аватары. Пароль нового
демо-пользователя случайный; для ручной проверки его отдельно задаёт оператор.
Пароли и файл тикетов не включаются в Git.

Демонстрация включается только `WORKS_TASKS_DEMO_FILE` в локальном окружении.
В `.env.prod.example` это поле пустое; реальный TT подключается настройками
из [PROD_ENV.md](PROD_ENV.md). В присланных карточках APPSEC нет сроков работ:
createdAt/updatedAt не используются как начало/окончание проекта.

## Редактирование и автоматический статус

Карточку проекта может редактировать любой его участник, администратор и создатель. Это не даёт права создавать/удалять проекты или управлять составом команды. UI отдельно проверяет видимость карандаша и корзины; backend проверяет членство на PUT.

`project_status_sync.py` использует общий минутный кэш APPSEC. При чтении Tasks синхронизация выполняется сразу, в фоне — раз в минуту. Обновление условное по старому статусу и текущей привязке: повторные синхронизации не дублируют аудит и уведомления. Изменение фиксируется в аудите с `source=appsec`, обновляет таймлайн и рассылается через WebSocket. Неизвестные состояния и недоступность TT сохраняют последнюю локальную стадию. Без привязанных проектов фоновый цикл не запрашивает TT.


| Состояния APPSEC (код или имя) | Статус STORM |
| --- | --- |
| qa, testing, Тестирование, open/new, in_progress | active |
| paused, on_hold, need_info, На паузе | freeze |
| handover_to_development, Передано в разработку | handover_to_development |
| vulnerability_recheck, retest, Перепроверка уязвимостей | vulnerability_recheck |
| done, completed, resolved, Выполнен | completed |
| closed, archived, cancelled, sent_by_mistake, Закрыт | archived |

При появлении нового состояния добавьте явное сопоставление в `project_status_for_task` и тест. Полный список возможных состояний конкретного промышленного workflow зависит от настройки TT.

Если привязанный тикет отсутствует в общем TQL-индексе (например, из-за архива или другого типа), фон догружает его карточку напрямую: не более 100 за проход и четырёх параллельных запросов. При большем числе пропусков проходы чередуются, чтобы не оставлять часть проектов без обновления. Сетевые ошибки сохраняют статус.
